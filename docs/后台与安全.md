# 后台与安全

后台只做四件事：**三个空间的在线人数**、**远程配置**（公告、官方时间校正、功能开关）、**匿名统计**、**管理后台**。
应用本身完全可以离线使用：后台没部署、断网、出故障时，礼拜时间、提醒、跟做、朝向都照常工作。

代码：`server/worker.js`（服务）、`server/admin/`（管理页面）、`shared/`（手机和服务共用的格式检查、签名）。

## 一、能远程控制什么（只有这些）

| 内容 | 说明 | 限制 |
|---|---|---|
| 公告 | 首页最上面的一段文字，最多 3 条，可设开始/结束日期 | 只显示纯文字，不能放链接、图片、网页代码 |
| 官方礼拜时间校正 | 某城市各番拜在计算值上加减几分钟 | 每次最多 ±30 分钟；**必须写明来源**，页面会显示"已按××校正" |
| 伊斯兰历调整 | 塔吉克斯坦、俄罗斯分别按当地宣布调整 ±2 天 | 必须写明依据；用户自己调过的以用户为准 |
| 功能开关 | 清真寺空间、在线人数、天气提示、匿名统计 | 只能"临时关闭"，不能打开新东西 |
| 提示更新 | 最低版本号 + 商店链接 | 链接只能是 Google Play、三星商店、App Store |

刻意**不能**做的：推送任意网页、改礼拜步骤和念词、收集任何信息、给某个人单独发内容。

## 二、防火墙和安全设计

1. **签名配置**：配置用管理员电脑上的私钥签名（ECDSA P-256），手机里只有公钥。
   服务器或管理口令被人拿到，也改不了手机上显示的内容；旧配置不能覆盖新配置（防回滚）。
2. **管理口令 + 两步验证**：口令至少 24 位，用 `wrangler secret` 保存，不写进代码；登录还要手机验证器上的 6 位数字，**同一个 6 位数字只能用一次**。
   登录后拿到 8 小时的签名会话，光有口令调不了任何接口。同一来源连续输错 5 次锁 1 小时；全局 1 小时内输错 30 次，后台整体锁住 1 小时。
3. **限流**：每个 IP 每分钟公开接口最多 300 次、后台 30 次（Cloudflare 自带限流，计数不落盘）。
   房间里每个连接 10 秒内最多 20 条消息，刷屏直接断开。
4. **来源限制**：只接受本站网页和本应用（`https://localhost`、`capacitor://localhost`）发来的请求；`ALLOWED_ORIGINS` 没填时一律拒绝网页来的请求（不会因为忘了填就敞开）。只读人数缓存 5 秒，大量请求也唤不醒房间。
   注意：来源可以被脚本伪造，所以第 3 条限流和第 5 条检查才是真正的防线。
5. **严格检查**：请求大小（统计 1 KB、配置 64 KB）、字段、取值全部白名单检查，不认识的一律丢弃。
6. **响应头**：所有响应带 `nosniff`、`DENY`（不许被嵌入）、`no-referrer`、HSTS；
   管理页面有严格的内容安全策略（只能运行自己的脚本，不许行内脚本和外部资源）。
7. **不存个人信息**：IP 只用于限流和口令锁定，只在内存里、用摘要，不写存储。

测试：`npm i --no-save miniflare@3.20250718.3 && npm run test:server`（78 项，GitHub 发布前自动运行）。

## 二½、亲友圈（自愿加入）

- 不要手机号、不用注册：每台手机自己生成随机编号和随机密钥（只存在手机上），服务器只存密钥的摘要。
- 服务器存的只有：昵称（最多 20 字，不许网址）、最后打卡的日期、连续天数（可隐藏）、收到的预设提醒（看过就删）。不存礼了哪几番。
- 邀请码 10 位随机（去掉易混字符），圈主可以锁圈、移出成员；每圈最多 20 人；半年没打开的成员自动移出。
- 提醒只能从 4 句预设里选，同一个人一天最多给同一个人发 3 条；按 IP 限流；只接受本站网页和本应用的请求。
- 测试：后台测试里有 20 多项专门测冒充、乱码、满员、锁圈、限流。

## 三、匿名统计（可在应用设置里关闭）

**离线优先**：每个使用日在手机上记一条，先放进本机的待发队列（最多 60 条，约两个月）；
打开应用、回到前台、网络恢复时自动补传。补传的记录记到它自己那一天（最多补 30 天前的）。

一条里只有：哪天用了、应用版本、平台（网页/安卓/苹果）、界面语言、所选城市（"我的位置"只报最近的城市）、
第一次打开是哪一周（用来算留存）、是不是第一次打开、从哪来（分享链接 / 直接打开网页 / 应用商店）、
提醒开没开、字号档位、最近 7 天用了几天、上一个使用日用到了哪些功能、记了几番"已礼"、跟着做完几次礼拜。
没有设备编号、具体时间、位置；服务器只把它们加进每天的总数，**不保存单条记录**。出错时匿名报告错误信息（每天最多 3 条）。

后台能看到：每天使用的设备数、每天新增和来源、**按周的留存表**（某周的新用户之后每周还有多少比例在用）、
开着提醒的比例、平台和语言、城市分布、各功能使用率、每天记了几番"已礼"的分布、最近 7 天用了几天的分布、字号分布、版本、错误。
统计只保留约 13 个月。

> 应用商店隐私标签要如实填写：苹果填"用于分析的使用数据（不与身份关联）"，
> 谷歌数据安全表填"应用互动、诊断信息：收集、不共享、匿名、用户可关闭"。
> 如果决定完全不统计，把 `flags.stats` 关掉或不设置 `VITE_API_URL`，就可以填"不收集数据"。

## 四、部署步骤（上线时做一次）

**手机上就能做的完整步骤见 [后台部署步骤.md](后台部署步骤.md)**（GitHub 里点"部署后台"自动完成）。下面是用电脑命令行的做法。

需要一个 Cloudflare 账号（免费套餐够用）。

```bash
cd server
npx wrangler login
npx wrangler deploy                         # 记下地址，例如 https://masjid-api.xxx.workers.dev
npx wrangler secret put ADMIN_TOKEN         # 输入至少 24 位的随机口令（可用：openssl rand -base64 32）
npx wrangler secret put ADMIN_TOTP          # 两步验证密钥（见下面第 0 步）
```

0. **两步验证（必须）**：没有设置 `ADMIN_TOTP` 时后台不开放。打开管理页 → "密钥" → "生成两步验证密钥"，
   把那串字母填进手机上的 Google Authenticator（或 Microsoft Authenticator），再用上面的命令存到服务器。
   以后登录：口令 + 手机上的 6 位数字，登录后 8 小时有效；换口令或两步验证密钥后旧登录全部失效。

1. 打开 `https://<地址>/admin/`，用口令登录 → "密钥" → 生成新密钥。私钥文件**备份好、不要外传**。
2. 把显示的公钥填到：
   - `npx wrangler secret put CONFIG_PUBLIC_KEY`
   - GitHub 仓库 Settings → Secrets and variables → Actions → Variables：`VITE_CONFIG_PUBKEY`
3. GitHub 同一页再加变量 `VITE_API_URL` = 后台地址（https 开头）。
4. `wrangler.toml` 里 `ALLOWED_ORIGINS` 填网站地址（例如 `https://<用户名>.github.io`），再 `npx wrangler deploy` 一次。
5. 重新构建网站和应用（推送到 main 会自动构建）。

建议在 Cloudflare 后台再打开：Bot Fight Mode（挡自动脚本）、给 `/admin/*` 加 WAF 规则只允许你们所在国家访问。

## 五、日常使用

- **发公告 / 改时间**：后台 → 远程配置 → 修改 → 选私钥文件 → 签名并发布。约 5 分钟内所有手机生效（手机最多每 6 小时问一次，下次打开应用时更新）。
- **出问题时**：功能开关里关掉对应功能，手机上显示"暂时关闭"，核心功能不受影响。
- **回退**：远程配置 → 最近发布过的版本 → 载入 → 重新签名发布。
- **换私钥**：需要发布新版应用（旧应用只认旧公钥），平时不要换。私钥丢了，旧应用就收不到新配置了。
