# 安全检查报告（2026-11）

范围：网页 / 手机应用代码、后台服务、依赖库、安卓和苹果工程配置。

## 发现并已修复

| # | 问题 | 风险 | 修复 |
|---|---|---|---|
| 1 | 天气查询少了一行定义，正式环境里天气一直查不出来（上一版引入） | 功能失效 | 已修复，并加了测试（模拟真实查询） |
| 2 | 页面时间固定按 UTC+5 显示，俄罗斯城市会显示错 | 礼拜时间显示错误 | 按所选城市时区显示；测试检查全部 28 城晌礼都在当地正午前后 |
| 3 | 正式网站上 `?now=`（拨时钟）、`?weather=`（演示天气）也生效：别人发来一个链接就能让你看到错的时间 | 被人恶意误导礼拜时间 | 只在本机和预览版生效（`src/core/dev.js`），有测试 |
| 4 | 网页没有内容安全策略 | 万一混进恶意文字，可能运行外部脚本、把数据发出去 | 构建时加入：只能运行自己的脚本，只能连自己、天气服务和我们的后台；不带来源网址 |
| 5 | 在线人数服务发来的数据直接用于页面 | 服务器被攻破时可往页面插内容 | 手机端只接受数字和约定的事件名 |
| 6 | 通知点开后跳转的地址没检查 | 理论上可跳到非本应用页面 | 只接受 `#/` 开头的本应用地址 |
| 7 | 本机存储被清理一半或改坏时，部分页面会出错 | 打不开、显示异常 | 设置、赞念、小净、古兰经进度读出来都检查格式，坏了就回到默认；有测试 |
| 8 | 开发用的 `ws` 库有已公开的漏洞（只用于本机测试服务） | 低（不进应用） | 已升级；`npm audit` 0 个漏洞 |
| 9 | 天气请求带了来源网址 | 第三方知道用户从哪个页面来 | 不带 Cookie、不带来源网址 |
| 10 | 远程配置的发布时间格式不统一时，"新旧"判断可能出错；时间写到未来会让以后的配置都发不出去 | 配置卡住 | 统一格式；服务端拒绝未来时间；有测试 |

## 后台服务（新）

防火墙、口令锁定、签名配置、限流、请求检查、安全响应头，详见 `docs/后台与安全.md`。
自动测试 48 项（`npm run test:server`），每次发布前运行。

## 检查过、没有问题

- **个人信息**：没有注册、登录、手机号、Cookie、广告和第三方统计；红线测试会拦住这些代码。位置只在用户点"用我的位置"时读一次粗略位置，只在手机上用。
- **页面里显示的文字**：界面文字来自语言文件；后台发来的公告一律按纯文字显示；用户自己的记录只在本机。
- **安卓**：只允许 HTTPS（目标版本 36 默认禁止明文）、不允许混合内容、只申请通知和粗略位置；网页调试只在调试版打开。
- **苹果**：只允许 HTTPS（系统默认）；位置用途说明已写。
- **依赖库**：`npm audit` 0 个漏洞；版本锁定在 package-lock.json。

## 留给上线前

1. 部署后台时管理口令用随机生成的（`openssl rand -base64 32`），私钥离线备份。
2. Cloudflare 打开 Bot Fight Mode；`/admin/*` 按国家限制访问。
3. 系统自带的备份（安卓 Google 备份、苹果 iCloud 备份）会把本机设置和记录备份到**用户自己的**账号，我们看不到。保留它，换手机时记录不会丢；如果要求"绝对只在本机"，可以关掉（安卓 `allowBackup=false`）。
4. 商店隐私标签按 `docs/后台与安全.md` 第三节填写。
