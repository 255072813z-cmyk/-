# 后台管理方案：上架以后怎么控制

**一句话**：所有钥匙都在你一个人手里。别人想改手机上显示的任何内容，必须**同时**拿到两把：后台登录（口令 + 手机验证码）和签名私钥。只丢一把，什么也改不了。礼拜时间算法和宗教内容根本不能远程改，只能发新版应用、经过商店审核。

部署步骤见 [后台部署步骤.md](后台部署步骤.md)，安全设计细节见 [后台与安全.md](后台与安全.md)。

---

## 一、你手里的 7 把钥匙

| # | 钥匙 | 管什么 | 放在哪 | 备份 |
|---|---|---|---|---|
| 1 | GitHub 账号（用 Google 登录） | 代码、网站、自动部署 | Google 账号 + GitHub 都开两步验证 | GitHub 恢复码打印出来，放在家里安全的地方 |
| 2 | Cloudflare 账号 | 后台服务器 | 开两步验证；只有你一个成员 | 恢复码打印出来 |
| 3 | 管理口令 `ADMIN_TOKEN` | 登录后台的第一道门 | 手机"密码"应用里 | 同上 |
| 4 | 两步验证（手机上的验证器） | 登录后台的第二道门 | Google Authenticator | 那串密钥抄在纸上 |
| 5 | **配置签名私钥文件** | 发公告、时间校正、功能开关 | 只在你自己的手机或电脑里，**绝不发给任何人** | U 盘两份，放两个地方 |
| 6 | Google Play 开发者账号 + 上传密钥（keystore 文件和密码） | 安卓应用更新 | 账号开两步验证 | keystore 文件和密码离线备份两份 |
| 7 | Apple 开发者账号（你是"账户持有人"） | 苹果应用更新 | Apple ID 开两步验证 | 恢复联系人设成家里人 |

**原则**：这 7 样不告诉任何人，不发到聊天软件里，不拍照存在相册里。要别人帮忙时，给他一个**权限最小**的单独账号（见第四节），用完收回。

## 二、后台能远程改什么、不能改什么

**能改（每一样都要：登录后台 + 用私钥签名）**

| 内容 | 限制 |
|---|---|
| 公告 | 最多 3 条，只能是纯文字（不会显示链接），可以设开始和结束日期 |
| 官方礼拜时间校正 | 某个城市每番拜加减分钟，每次最多 ±30 分钟，**必须写明来源**，页面会显示"已按××校正" |
| 伊斯兰历调整 | 按国家 ±2 天，必须写明依据 |
| 功能开关 | 清真寺空间、在线人数、天气、匿名统计，可以临时关掉 |
| 最低版本 | 低于它的应用提示"请去商店更新" |
| 商店链接 | 只能是 Google Play、三星商店、App Store 的官方地址 |

**不能远程改（故意这样设计）**

礼拜时间的计算方法、所有宗教内容（念词、圣训、古兰经）、页面和程序。这些只能通过发新版应用改，要经过你自己发布、商店审核。所以**即使后台被攻破，也改不了礼拜时间和宗教内容**。

**多快生效**：发布后服务器 5 分钟内更新；手机在打开应用时去取（最多每 6 小时一次），全部手机收到最多约 6 小时。急事同时在你们的群里通知。

## 三、为什么别人改不了（六道防线）

1. **手机只认你的签名**：每台手机里存着你的公钥，收到配置先验签名，对不上就扔掉。别人就算控制了服务器，也发不出手机认的公告。
2. **发布要三样**：口令 + 手机验证器上的 6 位数字（**每个数字只能用一次**）+ 私钥签名。
3. **登录有记录、会锁**：成功和失败的登录都记下（时间、国家、IP 摘要），管理页"数据"最上面能看到。同一来源输错 5 次锁 1 小时；全站 1 小时内输错 30 次，后台整体锁住。
4. **旧的盖不掉新的**：配置有发布时间，旧配置不能覆盖新配置（防止别人重放以前的配置）。
5. **防火墙**：每个 IP 每分钟最多 300 次请求（后台 30 次）；只接受本网站和本应用的请求；请求大小、字段、取值严格检查。
6. **代码公开，但只有你能改**：GitHub 上只有你有写权限。别人复制代码改了，影响不到你的网站、后台和商店里的应用。部署后台还要你在 GitHub 上点"批准"（第四节设置后）。

另外：正式版网站上，地址后面加参数（拨时间、假天气等测试用的）一律不生效；用户在自己手机上改数据只影响他自己。

## 四、上架前一次性设置（照着一项项勾）

### GitHub（手机浏览器打开 github.com，点右上角头像）
- [ ] Google 账号开两步验证；GitHub：Settings → Password and authentication → 开 Two-factor authentication，下载恢复码打印
- [ ] 仓库 → Settings → Collaborators：**只有你自己**。（Claude 是通过"GitHub 应用"推代码的，上架后可以在 Settings → GitHub Apps 里撤掉它的权限，需要我改东西时再加回来）
- [ ] 仓库 → Settings → Rules → Rulesets → New branch ruleset：目标选 `main`，勾 **Restrict deletions**、**Block force pushes**
- [ ] 仓库 → Settings → Actions → General：
  - Workflow permissions 选 **Read repository contents and packages permissions**
  - Fork pull request workflows 选 **Require approval for all external contributors**
- [ ] 仓库 → Settings → Environments → New environment，名字填 `api` → 勾 **Required reviewers**，只填你自己 → 把 `CLOUDFLARE_API_TOKEN` 等机密放在这个环境的 Secrets 里（以后每次部署后台都要你点批准）
- [ ] 仓库 → Settings → Code security：打开 Secret scanning、Push protection、Dependabot alerts

### Cloudflare
- [ ] 开两步验证；Members 里只有你
- [ ] API 令牌用 "Edit Cloudflare Workers" 模板，只选你这个账号，设一年到期
- [ ] Notifications：打开 Workers 用量提醒
- [ ] 以后有了自己的域名：打开 Bot Fight Mode；给 `/admin/*` 加 WAF 规则，只允许你所在的国家访问

### 后台
- [ ] `ADMIN_TOKEN` 至少 24 位随机字符
- [ ] 两步验证：手机验证器里有 + 纸上备份
- [ ] 签名私钥：U 盘两份

### 应用商店
- [ ] **Google Play**：开发者账号开两步验证；开 **Play App Signing**（Google 保管签名密钥，你保管上传密钥，丢了可以申请重置）；开 **托管式发布**（审核通过后由你点"发布"才上线）；用 **分阶段发布**（先给 10% 的人，没问题再全量，有问题随时暂停）
- [ ] **App Store Connect**：你是账户持有人；每个版本选 **手动发布此版本**；用 **分阶段发布**
- [ ] 两个商店的开发者邮箱、手机号都是你自己的；名字"Ҷойнамоз / Joynamoz"在两个商店里先占下

## 五、日常怎么管

| 多久 | 做什么 | 花多久 |
|---|---|---|
| 每周 | 登录后台（`后台地址/admin/`）→ "数据"最上面看**最近登录**有没有陌生的国家或一串失败；看一眼错误报告 | 5 分钟 |
| 需要时 | 发公告 / 时间校正 / 伊斯兰历：后台"远程配置"填好 → 预览 → 选私钥文件 → 签名并发布 | 10 分钟 |
| 发新版 | 跟我说"发布" → 网站自动更新；应用：打包 → 提交商店 → 审核通过 → 你点发布（分阶段） | 1–3 天（审核） |
| 每年 | 换 Cloudflare 令牌、换 `ADMIN_TOKEN`（改 GitHub 里的值 → 运行"部署后台"） | 15 分钟 |

**费用提醒**：Cloudflare 免费套餐每天 10 万次请求。用户超过大约 1 万人时，升级 Workers 付费版（每月 5 美元，1000 万次）。到时候后台"数据"页能看到每天有多少设备。

## 六、出了事怎么办

| 情况 | 马上做 | 用户会怎样 |
|---|---|---|
| 公告发错了 | 立刻发一份新的配置（删掉或改掉那条），新的会盖掉旧的 | 已收到的手机最多 6 小时内更新 |
| 后台被大量请求攻击 | 远程配置关掉"在线人数"；严重时在 Cloudflare 暂停这个 Worker | 礼拜时间、提醒、古兰经等核心功能全在手机上，**完全不受影响**；只是人数、亲友圈暂时不显示 |
| "最近登录"里有陌生的失败 | GitHub 里改 `ADMIN_TOKEN` → 运行"部署后台" | 所有已登录的会话立即失效，对方要从头猜 |
| 验证器手机丢了 | 管理页"第一次部署：生成密钥" → 生成新的两步验证密钥 → 改 `ADMIN_TOTP` → 部署 | 旧验证码立即失效 |
| 签名私钥泄露 | 马上改口令和验证器（对方没有后台登录就发布不了）；我做一版新应用换新公钥 | 新版上架前，旧版仍然只认旧公钥，但对方进不了后台 |
| GitHub 账号被盗 | 用恢复码找回；改密码 | 对方最多能改网站；**改不了商店里的应用，也发不出手机认的配置**（没有私钥） |
| Cloudflare 账号被盗 | 找回账号；换令牌 | 对方**改不了手机上的公告和时间**（没有私钥）；最多让人数、统计暂时不可用 |
| 新版应用有严重问题 | 商店里**暂停分阶段发布**；远程配置提高"最低版本"，提示大家更新到修好的版本 | 大部分人还没收到有问题的版本 |

## 七、为什么说能控制 90% 以上，剩下的是什么

**你完全能控制的**：代码、网站、后台、远程配置、商店里发哪个版本、什么时候发。前提只有一个：**保管好第一节的 7 把钥匙**。

**控制不了的**（任何应用都一样）：
- 苹果、谷歌的审核和政策变化
- GitHub、Cloudflare、商店本身出故障（应用核心功能是离线的，受影响很小）
- 用户不更新应用、关掉通知
- 别人照着公开的代码另做一个应用：改不了你的应用，但可能用相似的名字 → 尽早在两个商店占住名字，有条件可以注册商标

## 附：这次加的保护

- 后台记下每次登录（成功、失败都记），管理页"数据"最上面能看
- 同一个 6 位验证码只能用一次
- 没填网站地址时，网页来的请求一律拒绝
- "部署后台"要经过 `api` 环境，可以设成必须你批准
- 打包手机应用的流程只有读代码的权限
